# 体验页设置同步验证

版本：0.1.0。日期：2026-09-15。

## 原因与修改

旧体验页入口始终使用默认设置，在扩展设置页保存的个人关键词没有传入体验页。关键词匹配本身可以识别正文或昵称中的字面内容，表情前缀不影响连续关键词匹配。

- 扩展内体验页通过现有设置读取与订阅机制，加载已保存的配置后再开放测试。
- 扩展设置保存后，体验页同步已保存的配置并重新检测已有样本，保留输入和样本。
- 同步仅传入配置快照；体验页本地试验、黑白名单操作和记录继续使用页面内存，不写回扩展配置或真实历史。
- 新的已保存配置会替换本页临时试验设置。重置演示清空样本并恢复已保存的扩展配置。
- 本地网页演示继续独立工作，并说明测试已保存规则需要从插件打开体验页。
- 设置读取失败时明确提示，不悄悄使用默认规则给出“未命中”的结果。

## 验证证据

- TDD：先用合成关键词复现默认配置导致未命中的问题；原检测器测试通过，体验页配置与入口测试失败；接线后对应测试通过。
- `npm run verify`：30 个测试文件、289 项测试通过，类型检查与 Chrome 生产构建通过。
- `tests/demo-page.test.tsx` 从实际体验页入口运行，使用合成扩展存储验证读取、跨页配置变化、延迟与失败状态、本地试验不写回以及无扩展 API 的网页模式。
- `tests/demo.test.tsx` 验证命中原因、实际折叠、保存配置变化后保留输入及重置行为。
- `tests/detector.test.ts` 使用合成昵称和正文验证表情后的字面关键词匹配。
- `npm run build:firefox`、`npm run zip`、`npm run format:check` 通过。
- 本地浏览器交互：保存合成关键词“青杉词”，返回体验页输入合成文本，显示“命中你的关键词：青杉词”和“已折叠个人规则”。
