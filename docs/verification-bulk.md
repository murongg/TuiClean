# 历史记录批量拉黑验证

> 以下保留旧版批量拉黑与页面菜单方案的历史验证记录。拦截记录页的拉黑入口已移除；共享网页接口用于帖文提示条中的单条 X 拉黑，相关证据见 [网页接口验证](./verification-api.md)。

版本：0.1.0。日期：2026-09-15。

## 范围与行为

用户选择提供本地与 X 两种批量操作，范围是当前筛选结果的全部作者，包含未展开的分页，按账号去重并跳过白名单。

- 本地批量添加独立账号键，跳过已有本地黑名单账号，不替换整份名单。保存失败显示错误，可以重试。
- X 批量启动前展示并固定名单，在新建的专用标签页中依次访问主页检查账号状态，跳过原本已拉黑账号，再访问原帖、校验身份并操作原生菜单；只关闭任务自己创建的标签页。
- 操作前重新读取白名单。停止消息、页面退出或扩展失效会取消后续处理；设置读取期间的取消也会生效。
- X 的新提示必须包含目标账号和明确成功含义，才作为提示确认；其他账号提示、用户名中的 blocked 字样和否定提示不作为成功证据。缺少提示时重新访问目标主页，以账号身份及原生状态按钮复核；明确错误仍暂停。
- 无法访问原帖、身份变化、错误或缺少明确确认时暂停。用户可以停止或继续剩余名单，已经提交的操作不会自动撤回。
- X 队列和进度只存在当前记录页内存中，不自动恢复。体验页只提供本地批量演示，禁用真实 X 批量。

## 验证结果

先加入失败测试，再实现批量存储、队列、原生确认、内容消息和页面操作。

- npm run verify：22 个测试文件，210 项测试通过；类型检查及 Chrome 生产构建通过。
- Firefox 构建、Chrome ZIP 打包和格式检查通过，权限仍只有 storage，版本仍为 0.1.0。
- 覆盖跨分页去重、白名单、并发追加、保存失败、名单快照、账号身份、标签页所有权、取消、超时、暂停与剩余任务继续。
- 实际体验页按垃圾广告筛选后，批量本地拉黑 1 个作者，成功反馈及本地已拉黑标记正常。
- 390 px 窄屏的视口宽度与内容宽度均为 390 px，无横向溢出。
- 独立审查未发现需要修复的问题；审查中的 6 个相关测试文件共 42 项测试通过。

## 确认按钮兼容修复

- 根据“X 确认按钮已变化”的反馈，定位到原先直接对按钮 `textContent` 做整段精确匹配的校验。
- 在当前 X 页面和独立新标签页只打开并取消原生确认框，均观察到正常的 `Block` 按钮；未在真实页面复现最初的异常，也未提交真实账号拉黑。
- 合成 DOM 测试复现了按钮文字尚为空、按钮禁用或正在加载时立即误报的路径。现在等待按钮就绪后再校验，并优先读取渲染文字、去除不可见方向字符。
- 点击前再次核对按钮动作及可用状态，继续拒绝取消、举报、解除拉黑等其他操作；未知文案会在错误中显示，便于排查。
- `npm run verify`：22 个测试文件、253 项测试通过，包含新增的 15 项回归测试；类型检查及 Chrome 生产构建通过。版本保持 0.1.0。

## 验证边界

真实 X 的菜单、确认按钮及主页拉黑状态已检查。用户反馈“已提交但未确认”后，只读访问对应账号主页，确认其实际上已处于拉黑状态；排查过程没有重新拉黑或解除拉黑任何真实账号。更新后需重新加载扩展，并重新打开拦截记录页。

## 提交结果复核修复

- 原流程只等待短暂成功提示，缺少提示时即使拉黑已生效也会暂停。现在仅在缺少提示时访问新的主页页面复核，明确 X 错误不会被覆盖成成功。
- 每个账号操作前先检查主页状态，已拉黑账号无需访问被遮挡的原帖即可跳过；复核过程中不会再次提交拉黑。
- 状态读取同时核对 HTTPS 站点、主页路径、显示的账号及其头部原生按钮，排除隐藏控件、正文和推荐账号。
- 复核为未拉黑、无法确认、超时或用户取消时不继续提交其他账号。取消时只关闭任务自己的标签页。
- `npm run verify`：23 个测试文件、278 项测试通过，类型检查及 Chrome 构建通过。
- 已将实际状态读取函数以只读方式用于真实 X 页面，分别得到 `blocked` 和 `unblocked`；未执行真实批量提交测试。合成测试覆盖无提示但复核成功后继续队列、已拉黑跳过、复核失败暂停、取消、错误提示与推荐账号干扰。

## 主页辅助检查修复

- 用户报告主页状态检查导致任务暂停。只读检查对应主页时，页面可正常访问，现有函数返回 `unblocked`，并观察到扩展内容脚本已启动；未复现最初的连接或加载失败，也未提交真实拉黑。
- 修复把主页辅助检查设为硬性前置条件的问题：状态未知或主页连接失败时，继续尝试原帖，仍必须通过原帖编号、作者、菜单和确认账号的独立检查。已明确拉黑的账号仍提前跳过。
- 提交后缺少确认的复核规则保持：主页无法证明已拉黑时仍暂停，不会再次提交。
- 页面连接超时现在提示“无法连接 X 页面脚本”，显式页面错误直接保留，避免全部混为账号不可访问。
- `npm run verify`：24 个测试文件、303 项测试通过，包含新增的 6 项回归测试；类型检查及 Chrome 构建通过。取消、原帖不可验证与连接失败均未提交拉黑。

## 原帖菜单就绪修复

- 针对“未找到这条内容的 X 菜单”排查了批量任务实际访问的原帖。页面加载完成后，目标菜单及原生确认框可用；核对后取消，未提交真实账号拉黑。
- 原逻辑仅凭帖文编号和作者报告就绪，随后立即查菜单。合成场景复现了文字先出现、菜单稍后挂载或启用时的同类报错。
- 批量就绪检查现在同时要求目标帖文自己的可用菜单；原生操作还会等待暂时缺失的菜单，覆盖解除折叠后控件重新出现的场景。
- 菜单选择复用帖文的归属边界，排除引用帖、其他帖文、禁用和不唯一的候选。等待期间维持互斥锁、账号校验及取消处理。
- 新菜单读取函数已在真实目标页面以只读方式返回正确的 More 控件。浏览器验证停在原生确认提交之前；完整提交及结果路径由合成页面覆盖。
- `npm run verify`：24 个测试文件、309 项测试通过；类型检查及 Chrome 构建通过。新增 6 项测试覆盖延迟挂载、禁用后启用、取消、身份变化、菜单归属和折叠恢复后的完整消息流程。

## 先恢复页面再检查菜单

- 发现准备顺序缺陷：原帖仍被折叠时检查菜单，只有检查通过才暂停过滤；菜单如果要在展开后挂载，会互相等待。合成页面测试重现了该顺序问题。
- 现在对已验证身份的目标原帖先暂停操作页过滤，再重新定位目标及检查菜单；不匹配的页面不会被准备。准备后身份变化仍拒绝继续。
- 批量操作改为前台标签页。浏览器只读工具在检查页面时会使其可见，因此本轮前后台对照未能直接证明用户后台环境的渲染差异；不将此当作已经证实的唯一原因。
- 就绪失败包含前后台、文档状态、帖文数量及是否仍被折叠的诊断信息，区分“未匹配原帖”和“菜单未就绪”。
- 暂停时先请求取消动作，只有页面明确确认停止后才保留并显示操作页。不能确认停止时关闭自有页面；正常完成和用户停止仍关闭自有页面。
- `npm run verify`：24 个测试文件、315 项测试通过，类型检查与 Chrome 构建通过。新测试覆盖准备顺序、重验身份、诊断输出、失败现场保留及安全关闭、收尾期间取消。真实批量账号提交仍需用户重试验证。
